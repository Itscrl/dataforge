# Dataforge working agreements

- The owner requests incremental commits while work is still being built. Commit and push each meaningful implementation or documentation increment to the configured GitHub repository. Use a descriptive conventional-style subject and a body explaining behavior, motivation and validation. Mark unfinished integration work WIP in the body. Report failed checks honestly.
- Preserve the existing private Sites project ID and access policy. GitHub pushes and Sites publication are separate operations. Do not leave a completed website change only in GitHub when publication is requested.
- The owner explicitly requested Android APK packaging on 2026-11-09. Keep desktop packaging deferred until separately requested. Preserve the Android package ID and signing key for compatible updates.
- Never include provider secrets or OAuth tokens in source, build output or commits. Google OAuth client IDs are public identifiers; client secrets and tokens are not.
- Research answers must preserve document identity, physical PDF page, immutable document hash, chunk range and exact supporting excerpt. Verify source quotes before displaying generated factual claims. Do not label quote matching as proof of semantic correctness or currentness.
- Maintain publisher license and attribution notices for every bundled reference. A catalog link is not an indexed document; external downloads that failed must stay labeled as such.
- Test changes at phone and desktop widths in light and dark themes. Keep learning progress migrations backward compatible, and do not silently overwrite cloud or local data.
